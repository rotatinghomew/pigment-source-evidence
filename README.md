# 颜料批色漂资料交换

`data/` 收录供演练使用的合成记录，不含真实企业或人员资料。资料使用 UTF-8 逗号分隔，首行为字段名，带逗号的单值用双引号括起。日期采用 ISO 表示，空字段表示来源未填或不适用，不代表数值零。`sources.json` 记录各表列名、身份键和可直接核对的引用。

## 业务资料

- `source_batches.csv`：供应批标称色值及合格料最大可贡献量，色值为仪表统一刻度。
- `scale.csv`：料批的称重，可见时间与称量窗口不同；weight_min/max 单位千克。repair_of 指明确被替换的称量凭证。
- `vessels.csv`：罐事件，清空表示其前装料不能继续供其后工件。
- `links.csv`：在制和已发订单用料窗口、总重量及工位。
- `retains.csv`：允许误差为仪表读数 +/- error，不用来扩展某个订单的标准。
- `isolation.csv`：可用隔离位、适配位置、限量及已执行记录。
- `inquiries.csv`：补证候选、窗口和占用人力。不能同时做的取样共享同一个工位资源。

同一罐以最后一次明确清空为时间界线；称量窗口和用料窗口可能相交。料量单位均为千克。色值是该项目的合成归一化读数，混合值按已分配的组成质量解释；留样的测量误差是区间，不是供料标签。已发件不占隔离位；一个在制订单不能跨物理隔离位拆放。

## 本地核对

需要 Python 3.11。分析环境可使用 `python3 -m pip install -r requirements.txt` 安装锁定的数值依赖。

从仓库根目录执行 `python3 check_sources.py`，返回各表行数；其他同格式资料可用 `python3 check_sources.py 路径` 检查。脚本只读资料并报告结构或引用错误，不给出业务结论。执行 `python3 -m unittest discover -s tests -v` 检查资料约定及拒绝重复身份的行为。

## 色漂研判（drift 包）

`drift/` 在交换资料之上实现批源研判，不为每个工件单点挑“最像来源”，而是保留时间与用量约束下**所有能同时成立的解释**：

- **场景**：每张 `repair_of` 补称生成“维持原称 / 采纳补称”互斥场景（笛卡尔积）；补称替换的是该罐清空界内全部供料关系，不只改所在订单。
- **可行性（线性规划）**：罐以最后一次清空为界；称量入罐不晚于用料结束且未跨清空才可能供料；工件按总重量完整分配，受称带上限与供应批可贡献总量约束，混料不能攒出名义上从未投入的质量。
- **证据约束**：每份留样只生成一组误差带约束（按批标称中心值的混合读数落在 `value±error` 内），同一留样不拆成两个来源的独立证据；留样带不扩展订单标准。异常判据是误差带与产品订单范围无交集；未留样不等于正常。
- **共同解释**：在与全部留样相容的分配空间内判定每工件的可能/必然批源，求覆盖全部异常的极小高漂批组，并区分“所有解释均涉入 / 部分解释涉入 / 现有资料排除”。色号相关只用于圈定候选，不推因果。
- **隔离**：已发件进通知待审且不占隔离位；在制件按必停优先、best-fit 限量安置，一个订单不跨隔离位；排不下的件保留在未安置清单并注明所缺资源，不给出货结论；被排除件只作有条件放行，须签认。
- **补证排程**：同班组时间窗相交的候选互斥；按“能排除多少彼此冲突的解释”计分排序，而不是只测最大一单，并给出全部备选组合。
- **案卷**：`events.jsonl` 只追加。停用/通知动作是已执行事实，重开研判时原样保留；新观察触发新快照，只更正尚未执行的范围。

命令：

```bash
python3 -m drift.cli report data                      # 直接输出研判与隔离单
python3 -m drift.cli open data --case case/c1        # 建立案卷（含首版快照）
python3 -m drift.cli action case/c1 hold J3 --detail 移入I3
python3 -m drift.cli reopen case/c1 新资料目录 --observation "现场补回称量"
```
